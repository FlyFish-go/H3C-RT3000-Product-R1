## What R1-NET-D fixed

The WAN port (SSDK port 1 / GMAC0) is a **PHY-managed non-force port**. The MP adapter bound
`ssdk_port_speed_clock_set()` to `force_port == A_TRUE`, so GMAC0's speed clock was never programmed
and the RCG stayed on `xo / 24 MHz` — every 1000BASE-T frame failed CRC.

R1-NET-D decouples speed-clock programming from the force-only gate, keeps the forced-port-only MAC
operations gated, and removes the duplicate runtime clock call so each port programs exactly once.

Verified on hardware: GMAC0 RX/TX both `P_GEPHY_TX` @ 125 MHz; WAN RX clean (`RxFcsErr = 0`,
`RxFragment = 0`); DHCP, default route, gateway and internet all pass.

## Acceptance criterion (important)

Read **`gmac0_rx_clk_src`** and **`gmac0_tx_clk_src`** — parent and effective rate.

> **Do not** use `gephy_gcc_tx enable_count` as a pass/fail gate. It is a software shadow clock with
> no `.enable` op, so its count cannot be meaningful. This was a real methodology error earlier in the
> project; do not reintroduce it.

## Selector safety

Writes to the BOOTCONFIG selector must use **binary-safe** generation — pre-generated bytes or
base64. Never synthesise the selector byte through nested shell/`printf` escaping: that once wrote
the literal ASCII `\001` instead of the byte `0x01` (caught by the structural verify).

Every copy: **write → raw readback → structural BOOTCONFIG parse → exact selector verify.** Touch the
second copy only after the first fully verifies.
