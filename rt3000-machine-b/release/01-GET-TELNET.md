# RT3000 刷机教程 · 第一部分：获取 telnet

[← 教程总览](INSTALL.md)

> **适用范围**：仅在 RT3000 Machine-B（`GD5F1GQ5REYIG` NAND、原厂 `RT3000V100D009`）验证。A/C 样机以及 RW3000、RC3000、NX30 请勿套用镜像或刷写命令；无法确认硬件时先停下。


> **本部分目标**：让设备可以 telnet 登录，拿到一个 root shell。
>
> **为什么需要这一步**：原厂固件默认**不开启 telnet**。而后续所有操作（写入 QSDK、切换槽位）都需要一个命令行环境。网页后台做不到这些。
>
> **前置条件**：设备当前运行原厂系统。本部分的地址、网页菜单和备份格式都按原厂系统说明；若当前运行 QSDK，先核对当前系统，不要照此导入配置。
>
> **本部分只做一件事**：开启 telnet 并成功登录。导入修改后的备份会更改原厂系统的持久配置并使设备重启；本部分不直接擦写 `mtd15` 或 `mtd16` 固件分区。

> ⚠️ **网络边界**：Telnet 传输不加密。此设备的原厂有线桥接模式可让同一上游局域网访问管理口；只在可信、受控网络中操作，不要向互联网转发 23 端口。启用后 Telnet 会留在原厂配置中。完成教程后如决定关闭，须先安排其他可靠的原厂登录或 TTL 回切途径；关闭 Telnet 会失去本教程免 TTL 的原厂命令行切换路径。

## 0. 开始前你需要知道的

### 0.1 这台设备有两个系统槽位

RT3000 的 NAND 里有**两个独立的系统槽位**：

| 槽位 | 分区 | 装什么 |
|---|---|---|
| A | `mtd15` | **原厂系统**（出厂就有，我们全程不碰） |
| B | `mtd16` | 全新原厂设备上预期未安装 QSDK；曾刷过机的设备可能已有内容 |

机器上有一个 **selector**（选择器）决定**下次从哪个槽位启动**。

> **这意味着**：只要我们不动 A 槽，**原厂系统的内容就会保留下来**。
> 这一部分我们连 B 槽都不碰。
> 第二部分会先核对实际槽位与分区状态，不能仅凭本表认定 B 槽为空。
>
> ⚠️ 注意：**「内容保留」不等于「一定能回去」** ——
> 切回原厂需要一个能运行命令的环境。详见[第二部分 0.2 节](02-INSTALL-QSDK.md#02-有哪些保护机制以及它们的边界)。

### 0.2 设备的管理地址（取决于你怎么连它）

> ⚠️ **先声明测试环境**，否则下面的结论会被误读：
>
> **本教程的测试环境是 —— RT3000 的 WAN 口接在上游路由器上**，
> 由上游路由器（例如 `192.168.1.1`）负责分配 IP。

在这个环境下，原厂固件默认是 **「有线桥接」模式**。

#### 关键：管理地址取决于「用哪种方式连设备」

| 连接方式 | 设备的管理地址 | 说明 |
|---|---|---|
| **连设备的 WiFi** | **`192.168.10.1`** | 设备自己在这个网段提供管理地址 |
| **网线插设备的 LAN 口** | **上游路由器分配的地址**（如 `192.168.1.200`） | LAN 口被桥接出去了，与上游同网段 |

**这两种方式拿到的是不同的地址，都能进后台。**

> 📌 本教程后续用**网线插 LAN 口**的方式（管理地址形如 `192.168.1.x`），
> 因为这样电脑可以直接访问设备，不需要连 WiFi。

如果电脑已经连着**上游路由器**的 WiFi，而 RT3000 的 WAN 也接在该路由器上，原厂管理地址在当前实测接线下同样可由上游网络访问；先按第 2 节确认实际 IP 和网页连通。切到 QSDK 后管理服务只在 RT3000 LAN 侧开放，本机改由接在 LAN1 的跳板机访问 `192.168.10.1`。

#### 连 WiFi 时的网关

| 场景 | 连 WiFi 后的网关 |
|---|---|
| WAN 口接了上游路由器 | **`192.168.10.1`** |
| WAN 口没接 | **`192.168.10.1`** |

**无论 WAN 口接不接，连设备 WiFi 拿到的网关都是 `192.168.10.1`。**

#### 一个容易困惑的现象

如果你用网线插 LAN 口，会发现：

- ❌ `192.168.10.1` **打不开**
- ❌ 路由器后台里**找不到** DHCP 服务器设置

**这不是故障** —— 因为桥接模式下，LAN 口和上游路由器是同一个网络，
设备自己不在这边提供 `192.168.10.1`。

**遇到这种情况，用第 2 节的方法按 MAC 地址找它的真实 IP 即可。**

### 0.3 出厂默认密码

| 用途 | 用户名 | 密码 |
|---|---|---|
| **网页后台** | `admin` | `admin` |
| **WiFi** | — | **设备底部贴纸上的密码** |
| **telnet（开启后）** | — | `admin` |

> **关于网页后台密码**：设备第一次进入后台时会要求你**设置**管理员密码。
> **本教程按「默认设置、未设置密码」处理，所以后台密码就是 `admin`。**
> 如果你已经设过别的密码，用你自己设的那个。

#### ⚠️ telnet 密码（这是一个坑）

开启 telnet 后登录时，设备会显示一句提示：

```
 ==================== IMPORTANT ============================
  Use 'passwd' to set your login password!
 ----------------------------------------------------------
```

**这句提示是误导性的** —— 看起来像「还没设密码」，但实际上密码是存在的：

| 情况 | telnet 密码 |
|---|---|
| **没改过 WiFi 密码** | **`admin`** |
| 改过 WiFi 密码 | 可能同步为 WiFi 密码 |

**实测记录**：本教程设备的 WiFi 密码用了贴纸上的密码，但 **telnet 密码仍是 `admin`**（用贴纸密码会登录失败）。

**建议**：**先试 `admin`**，不行再试贴纸上的 WiFi 密码。

## 1. 准备工作

### 1.1 硬件

| 需要 | 说明 |
|---|---|
| RT3000 一台 | |
| 网线一根 | 电脑 ↔ RT3000 |
| 电脑一台 | Windows / macOS / Linux 都行 |
| 一根针或取卡针 | **不需要**。本方法不需要按 reset |

> ✅ **本部分不需要 TTL 串口线，不需要拆机。**

### 1.2 接线方式

```
     上游路由器（提供 DHCP，例如 192.168.1.1）
          │
          │ 网线
          │
    ┌─────┴──────┐
    │  RT3000    │
    │  WAN 口    │ ← 接上游路由器
    │  LAN 口    │ ← 接你的电脑
    └─────┬──────┘
          │
       你的电脑
```

**要点**：
- RT3000 的 **WAN 口**接上游路由器
- RT3000 的 **LAN 口**接你的电脑
- 这样电脑和 RT3000 **在同一个二层网络里**，可以互相访问

> 另一种已实测接法：RT3000 LAN1 接跳板机，电脑只连上游路由器 WiFi。原厂侧通过上游网段访问设备，QSDK 侧通过跳板机访问设备；不需要为了核对原厂而拔掉跳板机。

> 💡 如果暂时没有上游路由器，也可以只用一根网线把电脑和 RT3000 的 LAN 口直连 —— 但那样设备拿不到 DHCP 地址，需要另想办法。**推荐按上图接。**

### 1.3 软件

**只需要一个能 telnet 的客户端**：

| 系统 | 工具 |
|---|---|
| **Windows** | 见下方说明 |
| macOS / Linux | 终端自带 `telnet` |

#### Windows 用户：开启 telnet 客户端

Windows 的 telnet 客户端**默认是关闭的**，需要手动开启（**只需一次**）：

**方法一（图形界面）**：
1. 按 `Win + R`，输入 `optionalfeatures`，回车
2. 勾选 **「Telnet 客户端」**
3. 确定，等它装完

**方法二（命令行，管理员权限）**：
```cmd
dism /online /Enable-Feature /FeatureName:TelnetClient
```

**方法三（不装也行）**：用 **MobaXterm**、**PuTTY**、**Xshell** 等任意 SSH/telnet 客户端，选 **Telnet** 协议即可。

> ⚠️ Windows 自带的 `telnet` 有个缺点：**输入看不见光标**，且**不能复制粘贴**。如果觉得难用，用 MobaXterm 体验会好很多。

## 2. 找到设备的 IP 地址

因为设备是**桥接模式**，它的 IP 是**上游路由器分配的**，可能是 `192.168.1.x` 里的任意一个。

### 2.1 先看路由器后台（最简单）

登录你的上游路由器后台，找 **「已连接设备」/「DHCP 客户端列表」**，找名字类似这些的：

```
H3C
RT3000
H3C-Magic-RT3000
```

记下它旁边的 IP。

### 2.2 如果找不到，用 MAC 地址扫

> 💡 每台设备的 MAC 地址各不相同，但**同一个厂商有固定的前缀**（OUI，IEEE 公开注册）。
> H3C 设备的 MAC 通常**以 `58:B3:8F` 开头** —— 用这个前缀就能在网段里筛出 H3C 设备。
>
> （这是**厂商前缀**，不是某台设备的唯一标识；上面那串完整 MAC 才是设备独有的。）

**Windows（PowerShell）**：
```powershell
arp -a | findstr "58-b3-8f"
```

**Linux（GNU `md5sum` 与 GNU `sed` 环境）**：
```bash
arp -a | grep -i "58:b3:8f"
# 或
ip neigh | grep -i "58:b3:8f"
```

**如果 ARP 表里没有**（设备刚重启，表里还没记录），可以先 `ping` 一下整个网段：

**Windows**：
```cmd
for /L %i in (1,1,254) do @ping -n 1 -w 100 192.168.1.%i >nul
arp -a | findstr "58-b3-8f"
```
（把 `192.168.1` 换成你的网段）

**Linux**：
```bash
nmap -sn 192.168.1.0/24    # 或用 arp-scan -l
arp -a | grep -i "58:b3:8f"
```

### 2.3 验证

拿到 IP 后，先确认能通：

```bash
ping 192.168.1.xxx
```

再确认网页能打开：

```
http://192.168.1.xxx
```

**应该看到 H3C 的登录页**。

> 📌 **本教程后续用 `192.168.1.200` 作为示例**，你的地址可能不同，请自行替换。

## 3. 进入网页后台，导出配置备份

### 3.1 登录

浏览器打开 `http://<设备IP>`，用管理员账号登录。

- 如果是**刚恢复出厂**的设备，会让你**先设置管理员密码**（本教程示例设为 `admin`）
- 如果已经设过，用你设的密码

### 3.2 切到「专业版」

原厂后台默认可能是**简化版**。找到左下角的 **「专业版」** 切换按钮并点击。

> 简化版没有我们需要的功能，必须切到专业版。

### 3.3 导出配置

1. 左侧菜单 → **设备管理**
2. 上方标签 → **配置管理**
3. 找到 **「备份系统设置信息」**
4. 点击 **「备份」** 按钮
5. 浏览器会下载一个文件，名字类似 `RT3000.cfg`

**保存好这个文件** —— 它是你的**原始备份**，出问题可以恢复。

> ⚠️ **强烈建议**：把原始文件**另存一份**再改。例如：
> - `RT3000-original.cfg` ← 原始，永不修改
> - `RT3000-telnet.cfg` ← 我们要改的

### 3.4 备份文件长什么样

用**记事本**打开（或任何文本编辑器），你会看到：

```
c9c6ec7bc2c0aaf932ccc12f22e2bc9f  /var/run/.tmpcfg
RT3000/RT3000V100D009
$sys
@base
#<TAB>if-type=root
<TAB>ifname=root
<TAB>name=H3C_RT3000
...
@telnet
#<TAB>telnetenable=disable        ← 就是这一行
@login
#<TAB>loginpassword=<一长串密文>
...
```

#### 文件结构说明

| 部分 | 说明 |
|---|---|
| **第 1 行** | **MD5 校验值** + 一个固定路径 `/var/run/.tmpcfg` |
| **第 2 行** | 机型 / 固件版本 |
| **第 3 行** | 配置域标识 |
| **之后** | 以 `@` 开头的段落，每个段落里是 `键=值`，每行**以 TAB 开头** |

**关键**：
- 文件是**纯文本**，**LF 换行**（不是 Windows 的 CRLF）
- 配置项前的缩进是 **TAB 字符**（不是空格）
- **第 1 行的 MD5 必须与内容匹配**，否则设备会拒绝导入

## 4. 修改备份文件

### 4.1 找到要改的那一行

在文件里搜索 `telnetenable`，你会找到：

```
@telnet
#
	telnetenable=disable
```

**全文只有这一处。**

### 4.2 改成 enable

```
	telnetenable=enable
```

**注意**：
- ✅ 只把 `disable` 改成 `enable`
- ✅ **保留行首的 TAB**
- ❌ **不要在末尾加空格**（会被当成值的一部分）

### 4.3 重新计算 MD5 ⚠️ 关键步骤

**改完内容后，第 1 行的 MD5 就对不上了。必须重算。**

#### MD5 算的是哪部分？

```
第1行:  <32位MD5>  /var/run/.tmpcfg
        └────┬────┘
             └── 这 32 个字符要重算

从第 2 行开始的全部内容（即「第一个换行符之后」的正文）
        └── 对这一整块算 MD5
```

**规则**：`MD5( 第 1 行换行符之后的全部内容 )` = 第 1 行前 32 个字符

> ⚠️ **不要用「固定字节偏移」来定位正文。**
>
> 网上有些资料说「从第 52 字节开始」—— 那是基于**某一固件版本**第 1 行的
> `MD5(32) + 空格(2) + 路径(16) + 换行(1) = 51` 这一巧合。
> **路径长度一旦变化，这个数字就不对了。**
>
> **正确做法是「找到第一个换行符，从它后面开始」** ——
> 下面的脚本按这个方式处理，可适应**同一配置格式**中头部路径长度的变化；其他原厂版本若改变了配置结构或 `telnetenable` 键，必须重新核对，不能直接套用。

**为什么第 1 行要放个 MD5**：设备导入配置时会校验，
**内容被改过而 MD5 没更新 → 设备拒绝导入**。

#### ✅ 一键工具（推荐，已实测通过）

本项目提供一个 **Windows 一键工具**，把「改内容 + 重算 MD5」合成一步。

**两个文件**：

```
一键开启telnet.bat          ← 双击这个
RT3000-开启telnet.ps1       ← 核心脚本（和上面那个放一起）
```

**用法（二选一）**：

| 方式 | 操作 |
|---|---|
| **拖拽**（最快） | 把后台导出的 `.cfg` 文件**拖到 `一键开启telnet.bat` 上** |
| **双击** | 双击 `一键开启telnet.bat`，按提示把文件拖进窗口或输入路径 |

**输出**：在原文件名后加 `-telnet`，保存到同目录。例如输入 `RT3000.cfg` 会生成 `RT3000-telnet.cfg`；输入 `RT3000-original.cfg` 会生成 `RT3000-original-telnet.cfg`。如有重名，工具会追加序号。下文命令里的文件名请换成工具实际打印的输出路径。

**工具会自动做这些事**：

| 步骤 | 说明 |
|---|---|
| 1 | 检查文件头有没有被破坏（BOM / 格式） |
| 2 | **校验原文件完整性**（确认没被改动过） |
| 3 | 检查是否**已经改过**（改过就提示，不重复改） |
| 4 | 把 `telnetenable=disable` 改成 `enable` |
| 5 | **重算 MD5** 写回第 1 行 |
| 6 | **自校验**输出文件，失败就中止 |
| 7 | 另存为新文件，**原文件不动** |

**安全设计**：

- ✅ 原文件**只读**，不会被改
- ✅ 改前先验证、改后再验证
- ✅ 输出文件重名自动加序号，不覆盖
- ✅ 可以重复运行（已改过的会提示）

如果导出的配置里已经是 `telnetenable=enable`，工具会提示「已经开启」并结束，**不会再生成一份文件**；此时先按第 6 节检查 telnet 登录。若无法登录，先排查凭据与设备地址，不要把同一份配置反复导入。

> **运行环境**：Windows 自带 PowerShell 即可，**不需要安装任何东西**。
>
> 这个配置处理工具不需要管理员权限。若双击无响应，先从命令提示符运行 `一键开启telnet.bat` 查看报错，并检查原始 `.cfg` 所在目录是否可写；不要为排查工具启动问题直接提权。

#### 手动操作（不用工具的话）

如果想自己控制每一步，或不是 Windows 系统，可以手动做。**两个关键点**：

##### 1. 只改值，保留行首缩进

```
telnetenable=disable
└─ TAB（不同固件版本可能是空格），保持原样

telnetenable=enable      ← 只把 disable 改成 enable
```

> ⚠️ **不要在末尾加空格** —— 那会被当成配置值的一部分。

##### 2. 重算 MD5

**MD5 算的是哪部分**：

```
第1行:  <32位MD5>  /var/run/.tmpcfg
        └────┬────┘
             └── 这 32 个字符要重算

从第 2 行开始的全部内容（第一个换行符之后）
        └── 对这一整块算 MD5
```

> ⚠️ **按「第一个换行符」定位，不要用固定字节偏移**（原因见上文）。

**Linux / macOS**：

```bash
# 先改好内容，然后：
# ① 求出「正文起点」的字节偏移（第 1 行的长度 + 1）
#    用 awk 按字节算，不写死任何数字
OFF=$(awk 'BEGIN{RS="\n"} {print length($0)+2; exit}' RT3000-telnet.cfg)

# ② 用 tail -c 从该偏移取到文件末尾（字节级，不改动任何内容）
NEWMD5=$(tail -c +$OFF RT3000-telnet.cfg | md5sum | cut -d' ' -f1)

# ③ 写回第 1 行前 32 个字符
sed -i "1s/^[0-9a-f]\{32\}/$NEWMD5/" RT3000-telnet.cfg
echo "新 MD5: $NEWMD5"
```

> 💡 **为什么用「动态求偏移 + `tail -c`」而不是 `awk 'NR>1'`**：
>
> | 做法 | 问题 |
> |---|---|
> | `tail -c +52`（写死 52） | ❌ 依赖「路径恰好 16 字符」的巧合 |
> | `awk 'NR>1'` | ⚠️ **按行输出会补回行尾**：若原文件末尾**没有换行**，输出会**多一个换行**，导致哈希不符 |
> | **动态偏移 + `tail -c`** | ✅ **字节级原样搬运**，不增不减，也不依赖固定数字 |
>
> ⚠️ **前提**：文件必须是 **LF 换行**（不是 CRLF）。
> 检查方法见 [4.4 节](#44-验证你的修改)。

**Python（macOS 或其他跨平台环境推荐）**：

```python
import hashlib
p = "RT3000-telnet.cfg"
raw = open(p, "rb").read()
nl = raw.index(b"\n")                 # 第 1 行结尾
payload = raw[nl+1:]                  # 内容部分
new_md5 = hashlib.md5(payload).hexdigest()
out = new_md5.encode() + raw[32:nl+1] + payload
open(p, "wb").write(out)
print("新 MD5:", new_md5)
```

> ⚠️ **不要用记事本另存** —— 会加 BOM，破坏文件头。

### 4.4 验证你的修改

#### 先确认文件头没被破坏（Windows 用户必查）

**改完后，文件的前 3 个字节不应该出现 `EF BB BF`**（那是 UTF-8 BOM，会让设备拒绝导入）：

```powershell
# PowerShell
Format-Hex -Path RT3000-telnet.cfg | Select-Object -First 1
# 期望输出以 MD5 的第一个字符开头，例如 "2B E6 9B ..."
# 若看到 EF BB BF 开头 → 文件被写了 BOM，必须重做
```

```bash
# Linux / macOS
head -c 3 RT3000-telnet.cfg | xxd
# 同样不应是 efbbbf
```

#### 再核对内容

改完后，确认：

```bash
# 1. 第 1 行前 32 字符
head -c 32 RT3000-telnet.cfg; echo          # 应该是新的 MD5

# 2. 正文部分的 MD5（同样的动态偏移方式）
OFF=$(awk 'BEGIN{RS="\n"} {print length($0)+2; exit}' RT3000-telnet.cfg)
tail -c +$OFF RT3000-telnet.cfg | md5sum    # 应该和上面一致

# 3. 确认改动只有一处
diff RT3000-original.cfg RT3000-telnet.cfg
```

**`diff` 应该只显示两处改动**：

```diff
1c1
< c9c6ec7bc2c0aaf932ccc12f22e2bc9f  /var/run/.tmpcfg
---
> 2be69bba1bc19111841278f4f1bb03b3  /var/run/.tmpcfg
31c31
< 	telnetenable=disable
---
> 	telnetenable=enable
```

**只有 MD5 和 `telnetenable` 这两处不同 → 修改范围符合预期。**

## 常见问题

### Q1: 网页后台找不到「配置管理」/「备份」按钮

**原因**：还在**简化版**界面。

**解决**：点左下角的 **「专业版」**，再进 **设备管理 → 配置管理**。

---

### Q2: 恢复配置后设备没重启 / 提示失败

**最可能的原因**：**MD5 算错了**。

**排查**：
```bash
# 确认两处一致
head -c 32 改好的.cfg; echo
OFF=$(awk 'BEGIN{RS="\n"} {print length($0)+2; exit}' 改好的.cfg)
tail -c +$OFF 改好的.cfg | md5sum
```

**另一个可能**：文件被编辑器改坏了。有两个常见破坏方式：

| 破坏方式 | 后果 | 检测 |
|---|---|---|
| 写入 **UTF-8 BOM** | 文件头多 3 字节 | 前 3 字节是 `EF BB BF` |
| 换行变成 **CRLF** | 每个换行多 1 字节，头部长度错位 | 文件里出现 `0D 0A` |

**两个都要查**：

```bash
# 查 BOM（不应出现 efbbbf）
head -c 3 改好的.cfg | xxd

# 查 CRLF（输出 0 表示没有 CR；大于 0 再核对）
grep -c $'\r' 改好的.cfg
```

```powershell
# PowerShell
Format-Hex -Path 改好的.cfg | Select-Object -First 1  # 开头不应是 EF BB BF
(Get-Content 改好的.cfg -Raw) -match "`r"   # 应为 False
```

**编辑器设置**（Notepad++）：
- 编码 → **UTF-8**（**不带 BOM**）或 ANSI
- 编辑 → 档案格式转换 → **转换为 Unix (LF)**

**最保险**：从原始备份重新改一次，用脚本算 MD5。

---

### Q3: telnet 连不上

| 现象 | 原因 | 解决 |
|---|---|---|
| `Connection refused` | 目标地址的 23 端口未提供 telnet | 先核对设备 IP 和系统身份，再检查配置导入结果 |
| `Connection timed out` | 地址、接线或启动状态待确认 | 重新找 IP；等启动完成 |
| 能看到 `Password:` 但没有 H3C 提示符 | 认证状态或终端交互尚未确认 | 使用正常 Telnet 客户端核对当前密码；未看到 `<H3C_RT3000>` 前不要输入 `debugshell` |

### Q4: 密码 `admin` 和 WiFi 密码都不对

**可能原因**：当前原厂配置的管理密码与本教程默认示例不同，也可能是 Telnet 客户端没有正确处理协议或提示符。

先用正常 Telnet 客户端核对当前登录状态，并确认自己实际设置过的原厂后台密码；不要连续猜密码。若确实忘记密码，先保留现有配置备份，再单独决定是否恢复出厂。恢复出厂会清除原厂设置、关闭已开启的 telnet；不能把它当作无损重试。

### Q6: 这样做安全吗？会不会变砖？

**本部分不直接擦写 `mtd15` 或 `mtd16` 固件分区，但导入配置会修改原厂持久设置并重启。**

本部分**只**做了：
1. 导出配置（只读）
2. 改了一个开关的值
3. 导入配置

**没有直接写固件槽或 selector。**

如果导入后管理功能异常，先保留症状和原始备份，再决定是否恢复原备份或恢复出厂。恢复出厂会丢失当前原厂设置，并非回到导入前的逐字节状态。

---

### Q7: `Use 'passwd' to set your login password!` 是什么意思？

字面意思是「用 `passwd` 命令设置你的登录密码」。

这是 BusyBox 的通用提示，**不能据此判断 telnet/H3C CLI 当前是否需要密码**。只有成功看到 `<H3C_RT3000>` 并进入 shell，才算完成本部分；本教程不要求执行 `passwd`。
