# H3C Magic RT3000 刷机教程

> 在原厂系统之外安装 **QSDK（OpenWrt 21.02.7）**，并支持**在原厂与 QSDK 之间双向切换**。
>
> 正常安装与双向切换已走通**免 TTL** 路径；若两个系统都无法操作，救援仍可能需要 TTL 串口。

> **适用范围先看**：本教程的镜像与写入命令只在 RT3000 **Machine-B**（GigaDevice `GD5F1GQ5REYIG` NAND、原厂软件版本 `RT3000V100R005`）验证。A/C 样机以及 RW3000、RC3000、NX30 仍需各自的硬件调查与实机验收，**不要照本教程刷写**。

| 设备 / 硬件 | 本教程镜像与写入命令 | 状态 |
|---|---|---|
| RT3000 Machine-B；`GD5F1GQ5REYIG`；原厂软件版本 `RT3000V100R005`；启动配置 `config@mp02.1` | 适用，仍须逐项核对分区表 | 本轮完整实机走查 |
| RT3000 Machine-A / Machine-C 或其他 NAND、交换机、原厂版本 | 不适用 | 尚未对此镜像完成验证 |
| RW3000 / RC3000 / NX30 | 不适用 | 项目路线目标，尚未验证 |

### 🔴 不要默认适用于所有 RT3000

**RT3000 存在不同硬件批次/版本。** 以下情况**本教程未验证**：

| 情况 | 风险 |
|---|---|
| 不同 NAND 型号 | 分区布局、擦除块大小可能不同 |
| 不同硬件版本（如 Machine-A / Machine-C） | **分区表和 selector 位置可能完全不同** |
| 不同原厂固件版本 | 配置项名称、分区命名可能不同 |
| 运营商定制版本 | 出厂配置、默认密码可能不同 |

> **操作前请先核对**：
> ```sh
> # 在原厂 telnet 里
> cat /proc/mtd              # 看分区表和大小
> uname -r                   # 看内核版本
> ```
>
> **如果你的输出和上表不符，请先停下** ——
> 尤其**分区表不同**时，本教程的 `mtd15` / `mtd16` 引用可能**指向错误的分区**。

### 怎么确认自己是 Machine-B

原厂启动日志（串口）里会显示：

```
     Description:  ARM OpenWrt qcom-ipq50xx-mpxx device tree blob
   Using 'config@mp02.1' configuration            ← mp02 = Machine-B
```

以及 NAND 识别行：

```
Serial NAND device Manufacturer:GD5F1GQ5REYIG
```

**免 TTL** 指正常安装和双向切换时无需串口操作，**不免除刷写前确认硬件**。`cat /proc/mtd` 与 `uname -r` 只能核对布局和原厂内核，不能单独证明 NAND 型号及启动配置。若没有可信的启动日志、硬件标识或既有设备记录来确认上述 Machine-B 配置，先停在只读核对阶段，不要仅凭设备外壳上的“RT3000”执行写入。

## 安全说明的边界（重要）

刷机**有风险**：写错分区可能导致原厂系统丢失，硬件故障或意外断电可能导致设备无法启动。**请确认你理解每一步在做什么。** 本方案的保护机制不等于「一定救得回来」。

### 验证矩阵（2026-09-23 Machine-B 走查）

| 路径 / 事项 | 实测范围与边界 |
|---|---|
| 原厂 Telnet | 登录已实测；配置导入沿用早期实测，本轮未重复导入。一键工具在三份不同配置头的 RT3000 原厂备份副本上离线复核，输出分别与既有启用版逐字节一致，原文件未改变 |
| 从原厂安装 QSDK（B 方案） | 实机复走写入 `mtd16`、读回、NAND 启动和双频手机关联 |
| 读回校验参数与命令 | 镜像解析参数与清单一致；原厂实机复走 kernel/rootfs 哈希均匹配；`ubidetach` 报错后以 `/sys` 确认已分离 |
| 主动双向切换 | 再次往返；所测 QSDK 三个配置文件和测试标记的大小与哈希一致；原厂 Telnet 设置跨切换仍有效。**不代表两边所有配置都逐字节核对** |
| 保留配置升级 / `sysupgrade -n` | 两种路径与升级后的双频手机关联均实测；`-n` 只重置 QSDK，不重置原厂配置 |
| OEM `mtd15` 读取与备份传输 | 设备端完整读取 / SHA-256 已复走；**40 MiB 传输到电脑的最终教程路径尚未逐条复走**，备份可读不等于恢复已验证 |
| QSDK 启动失败自动回退 | **未验证**；不能由 selector 机制推导故障时的实际行为 |
| 故障注入 / 写入中断电 | **未实测**；写入时启动目标指向原厂只是保护机制，不是断电救援实证 |
| 两个系统都无法操作 | 可能需要 **TTL 串口 + U-Boot**；**完整 U-Boot + TFTP NAND 救援未端到端验证**。仅网络加载 initramfs 的 RAM 启动已有实证 |

> ⚠️ **不要把「镜像参数已核对」理解为「故障救援已端到端验证」。** 正常安装路径与故障救援路径的实测范围不同。
>
> **「原厂内容保留」不等于「一定能回去」。** 主动切回需要能运行命令的环境；两个系统都起不来时须具备串口救援条件。保护机制不能替代 **本机备份** 和 **TTL 救援准备**。

**首次设置**：原厂 Telnet 传输不加密，桥接模式下可能被同一上游局域网访问；只在受控网络中开启，不要转发 23 端口。QSDK 新装后立即设置 root 密码并更换公开的默认 Wi-Fi 密码。关闭原厂 Telnet 前先安排可靠的回切途径，否则免 TTL 回切会失去原厂命令行入口。

### 操作边界

本教程**不涉及**：

- 修改 bootloader
- 修改分区表
- 修改 U-Boot 持久化环境（不执行 `saveenv`）
- 写入 `mtd15`（原厂系统）

<a id="这个设备有什么特别的"></a>

### 系统槽位与 selector 保护机制

#### 两个系统槽位

RT3000 的 NAND 里有**两个独立的 40 MB 系统槽位**：

| 槽位 | 分区 | 内容 |
|---|---|---|
| A | `mtd15` | **原厂系统**（出厂就有） |
| B | `mtd16` | **QSDK**（我们装的） |

**selector**（选择器）决定下次从哪个槽启动：

```
selector = 0  →  启动原厂
selector = 1  →  启动 QSDK
```

#### 三个重要特性

**① 切换是免费的**

因为两个系统**同时存在**，切换只更新 `mtd2`、`mtd3` 中各一份 4 字节的 selector 字段 ——
不需要重新刷机，不会丢配置。

**② 原厂系统槽位保留**

我们**从头到尾不写 `mtd15`**，因此原厂槽内容保留。
这不证明它在任何故障后一定可启动；「切回去」仍需要能执行命令的环境 —— 详见上方验证矩阵。

**③ 写入有失败保护**

安装/升级 QSDK 时，流程是：

```
先把 selector 切到原厂  ← 保命
    ↓
再写入 mtd16
    ↓
校验通过后才切回 QSDK
```

**所以写入阶段失败时，设备会尝试启动原厂。**

> ⚠️ **但这条「自动回退」路径我们尚未实测。**
> 详见本节[安全说明的边界](#安全说明的边界重要)。

## 准备与备份

### 你需要准备

| 物品 | 说明 |
|---|---|
| 已确认符合上节 Machine-B 配置的 RT3000 | 不仅凭外壳型号判断 |
| 网线 | 连接电脑与设备 |
| 电脑 | Windows / macOS / Linux |
| 上游路由器 | 提供网络（**重要**，见下） |
| 一根针 | 用于 reset（**只在需要时**） |

> ✅ 正常安装路径不需要 TTL 串口线或拆机；若启动链或两个系统都不可操作，需另备 TTL 救援条件。

### 推荐接线

```
     上游路由器（提供 DHCP）
          │
    ┌─────┴──────┐
    │  RT3000    │
    │  WAN 口    │ ← 接上游路由器
    │  LAN 口    │ ← 接你的电脑 ⭐
    └─────┬──────┘
          │
       你的电脑
```

**为什么 LAN 口要接电脑**：
QSDK 的管理界面**只绑在 LAN 侧**。这样接，两种系统下都能访问设备，**不用拔线**。

### 进入刷写流程前：保存 OEM 备份

**先读[第五部分备份正文](05-RECOVERY.md#4-你的备份资产)**，再按下列顺序准备；不要等出故障后才开始备份。

1. 在第一部分[从原厂网页导出 `.cfg`](01-GET-TELNET.md#3-进入网页后台导出配置备份)，保留未修改的原件。
2. 取得原厂 root shell 后，按[原厂系统分区备份说明](05-RECOVERY.md#42-原厂系统的备份--请自己做一个)读取本机 `mtd15`，把备份保存在可信电脑上；核对文件长度为 **41,943,040 字节**，电脑端 SHA-256 与设备端完整读取的 SHA-256 一致。
3. 确认两份备份都能找到，再进入[第二部分安装流程](02-INSTALL-QSDK.md)。第 2 步的传输方法尚未按最终教程逐条实机复走；若无法完成或校验不一致，停在写入之前。

`mtd15` 的读取备份是故障准备，不代表其恢复路径已实测。不要公开上传这些含设备信息的备份。
