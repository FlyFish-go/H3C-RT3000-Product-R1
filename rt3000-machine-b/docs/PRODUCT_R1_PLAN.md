## 1. P0 release blockers (must close before Product R1 ships)

### RT3-RB001 — selector writer must verify per copy

**Status: OPEN**

`rt3bcwrite --set` writes both BOOTCONFIG copies in one invocation with no intermediate verify gate.
A failure between copies can leave the pair in an unverified mixed state.

**Required behaviour:**
```
mtd3 write -> verify -> mtd2 write -> verify
```
— each step failing closed before the next begins. A one-shot dual-copy write is forbidden.

**Note:** the strict ordering used in the R1-NET-D install was achieved with the separately built
single-copy tool, not the packaged one. The packaged tool still needs the gate.

### RT3-RB002 — `rt3slot` firmware identity must not use a fixed UBI `image_seq`

**Status: OPEN**

`rt3slot` uses a fixed UBI `image_seq` as firmware identity. This is a wrong design: `ubiformat`
**changes** `image_seq`, so the identity is not stable across a legitimate reflash.

**Required:** replace with a stable content identity — a FIT/kernel hash, a manifest, or an
equivalent content digest. **Do not** simply update the hardcoded `image_seq` constant.

### MAC policy (already frozen — implement, do not redesign)

The only trustworthy factory MAC is the **U-Boot env `ethaddr`**.

| Role | Rule |
|---|---|
| WAN | retain the factory globally-administered MAC verbatim |
| LAN | `HASH(factory_mac \|\| "lan")` → deterministic **LAA** |
| WiFi24 | `HASH(factory_mac \|\| "wifi24")` → deterministic **LAA** |
| WiFi5 | `HASH(factory_mac \|\| "wifi5")` → deterministic **LAA** |

Requirements: `stable`, `role-unique`, `multicast = 0`, `local = 1`.

**Forbidden:** random LAA; fabricating contiguous H3C global MACs.

## 4. Open network qualifications (carried from bring-up)

These are **not** release blockers but must not be recorded as PASS:

| ID | Item | State |
|---|---|---|
| NET-QUAL-001 | physical WAN unplug/replug at 1 Gbps | NOT TESTED |
| NET-QUAL-002 | 100BASE-T qualification | NOT TESTED |
| NET-QUAL-003 | 10BASE-T qualification | NOT TESTED |

Rationale for NET-QUAL-001 in particular: the R1-PROBE-I trace proved **no runtime link-event path
fires for the WAN port**. NET-D programs the clock at boot, which is sufficient for initial bring-up,
but whether a physical re-plug re-negotiates correctly is genuinely unverified. Pre-unplug reference:
`port:1 up 1000baseT`, both GMAC0 clocks 125 MHz, `eth0 rx_packets 842`.

## 5. Standing rules for all future device work

1. **Clock acceptance criterion** — read `gmac0_rx_clk_src` / `gmac0_tx_clk_src` parent + effective
   rate. **Never** use `gephy_gcc_tx enable_count`; it is a shadow clock with no `.enable` op.
2. **Selector writes** — binary-safe generation only (pre-generated bytes or base64). No multi-layer
   `printf` escaping. Every copy: write → raw readback → structural BOOTCONFIG parse → exact verify;
   the second copy only after the first fully verifies.
3. **Firmware transfer** — OneCloud LAN/HTTP only. **Never** over the TTL; TTL is boot console and
   recovery only.
4. **Device identity fence** — `192.0.2.1` on the jumpbox main netns is the **JCQ30Pro**, not the
   RT3000. Confirm identity before any IP-based action. The RT3000 is `00:11:22:33:44:55`, DT model
   `H3C Magic RT3000`, reached via the jumpbox `flash` netns USB NIC.
5. **OEM is the golden reference** — if hardware/BOM/PCB is ever suspected, first run a
   same-hardware OEM control experiment. Do not start by disassembling.
6. **Rollback anchor** — OEM mtd15, selector 0. Keep it intact.
